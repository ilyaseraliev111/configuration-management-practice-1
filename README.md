# Практическая работа №1 — вариант 28

Дисциплина: «Конфигурационное управление», РТУ МИРЭА, 2026/2027.
Основание: сборник практических работ №1, вариант 28, страницы 89–91;
правила оформления репозитория — страницы 4–7.

Полностью реализованы пять этапов эмулятора UNIX-подобной оболочки.
Язык — Python 3.10 или новее. Внешних зависимостей нет.

## Быстрый старт

Распакуйте проект и откройте терминал в папке `variant28`.

Linux, macOS, WSL:

```sh
sh run.sh
```

Windows (CMD или PowerShell):

```powershell
.\run.bat
```

Либо из корня проекта: `python3 -m src.main`.
В Windows вместо `python3` обычно используется `python` или `py -3`.
Если Python отсутствует, сначала установите Python 3.10+.
Сборка и установка пакетов не нужны: программа исполняется интерпретатором.

```text
ls
cd "space dir"
tail "hello world.txt"
cd /
touch new.txt
chown student:students new.txt
ls -l new.txt
du -s /
exit
```

Приглашение содержит настоящие имя пользователя и hostname, а путь — виртуальный.
`cd /` означает корень VFS, а не корень диска компьютера.

## Параметры запуска

| Параметр | Значение и назначение |
| --- | --- |
| `--vfs PATH` | Исходная папка, по умолчанию `examples/vfs/demo` |
| `--script PATH` | Стартовый сценарий UTF-8; по умолчанию отсутствует |
| `--batch` | Завершить работу после сценария, не открывая REPL |
| `-h`, `--help` | Справка по запуску |

Все заданные параметры выводятся при старте, как требует этап 2.
При запуске через run.sh/run.bat относительные физические пути считаются
от папки проекта. При `python -m src.main` — от текущей папки терминала.

```sh
python3 -m src.main --vfs examples/vfs/demo --script examples/stage4.txt --batch
python3 -m src.main --vfs examples/vfs/demo --script examples/stage5.txt --batch
```

Сценарий печатает приглашение и каждую исходную команду, затем её результат.
Первая ошибка выводит имя сценария и номер строки, останавливает сценарий
и приложение с кодом 1. Ошибка параметров argparse даёт код 2.
Успешное выполнение, exit или EOF — код 0. Без `--batch` после успешного
сценария открывается REPL, если в сценарии не было exit.
Ошибки команд в REPL не завершают программу. Ctrl+C отменяет текущий ввод.
EOF: Ctrl+D в Linux/WSL/macOS; Ctrl+Z и Enter в Windows.

## Команды и поддерживаемые режимы

| Команда | Синтаксис | Поведение |
| --- | --- | --- |
| `ls` | `ls [-al] [--] [путь ...]` | Содержимое каталога или сам файл |
| `cd` | `cd [--] [каталог]` | Переход, без аргументов — корень VFS |
| `du` | `du [-s\|-a] [--] [путь ...]` | Суммарные логические размеры в байтах |
| `tail` | `tail [-n N] [--] файл ...` | Последние N строк; по умолчанию 10 |
| `touch` | `touch [-c] [--] путь ...` | Создание пустого файла или обновление mtime |
| `chown` | `chown [-R] [--] владелец[:группа] путь ...` | Изменение владельца/группы |
| `exit` | `exit` | Завершение без аргументов |

- `ls -a` включает скрытые имена. `-l` выводит тип, владельца, группу,
  размер содержимого и время изменения. Для каталогов размер в `ls` равен 0.
  Разрешены `-al`, `-la`, `-a -l`. Синтетические `.` и `..` не выводятся.
- `du` по умолчанию показывает каталоги и отдельно указанные файлы;
  `-a` добавляет все файлы; `-s` показывает только итог каждого аргумента.
  `-s` и `-a` вместе отклоняются. Учитываются скрытые файлы.
- `tail -n 0` выводит пустой результат; отрицательное/нецелое N — ошибка.
  `-n` указывается перед путями. Для нескольких файлов печатаются заголовки.
  Текст должен быть UTF-8; бинарные файлы хранятся в VFS без изменений,
  но недекодируемые данные нельзя просматривать через tail.
- `touch -c` не создаёт отсутствующие файлы. Существующее содержимое сохраняется.
  Родительский каталог должен существовать. Время обновляется и у каталогов.
- `chown -R` обрабатывает поддерево; `chown :group file` меняет только группу.
  Разрешены имена вида `student`, `team-1` и числовые UID/GID.
  `owner:` без группы отклоняется. Изменения видны через `ls -l`.
- `--` завершает разбор опций и позволяет, например, `touch -- -file`.
- Пустой ввод допустим. Одинарные и двойные кавычки, экранирование пробелов
  обрабатывает `shlex.split(..., posix=True)`. Незакрытые кавычки — ошибка.

## Устройство VFS и границы эмуляции

Исходная папка рекурсивно читается один раз. Файлы хранятся как bytes,
каталоги и метаданные — как объекты Node в словаре абсолютных POSIX-путей.
Изменения теряются после выхода; перезапуск снова читает исходную папку.
Программа не распаковывает архивы, не вызывает системные touch/chown,
не меняет реальный рабочий каталог и не записывает данные в источник VFS.
Символические ссылки и специальные файлы отклоняются с понятной ошибкой:
они не позволяют выйти за пределы выбранного дерева.

Размер `du` — сумма байтов файлов, не объём выделенных дисковых блоков.
Начальный владелец и группа представлены UID/GID исходных объектов;
новые виртуальные имена не проверяются в системной базе пользователей.
Права доступа не эмулируются. Память должна вмещать всё содержимое источника.
Снимок делается при условии, что исходную папку параллельно не изменяют.

Это учебное подмножество оболочки, а не полноценный Bash: нет конвейеров,
перенаправлений, glob-масок, раскрытия `$HOME`/`~`, фоновых задач, комментариев
и произвольного запуска команд ОС. Такие возможности вариант 28 не требует.
`#` в сценарии не является комментарием. `tail -f`, символические ссылки,
`touch -t` и остальные неописанные опции не поддерживаются.

## Структура и функции

| Файл | Назначение |
| --- | --- |
| `src/main.py` | `parse_args`: настройки; `run_script`: диалог и остановка; `main`: запуск и коды |
| `src/shell.py` | `Shell`: сеанс; `prompt`: приглашение; `execute`: парсер/диспетчер; `repl`: ввод; `stub`: этап 1 |
| `src/vfs.py` | `Node`: данные; `normalized`: пути; `VFS`: снимок |
| `src/commands.py` | `arguments`: флаги; `Commands`: ls/cd/du/tail; `install`: регистрация |
| `src/mutations.py` | `Mutations`: touch/chown, разбор владельца |
| `tests/` | Автоматические проверки через unittest |
| `examples/` | VFS, стартовые сценарии, скрипты реальной ОС |
| `docs/` | Соответствие требованиям, подсказки к защите, результаты проверки |

Каждая функция имеет docstring. Внутренние методы VFS: `_load` читает дерево,
`get` проверяет объект, `children` возвращает прямых потомков,
`subtree` возвращает поддерево, `touch` изменяет время/создаёт узел в памяти.
Методы Commands: `path` разрешает путь, `listing` и `print_entry` печатают ls,
`cd` меняет cwd, `du` и `sizes` считают размеры, `tail` и `tail_args` читают хвост.
Методы Mutations: `touch`, `chown`, `owner_spec`.
Конструкторы связывают компоненты; дополнительные настройки не скрыты.

## Проверка

В корне проекта:

```sh
python3 -m unittest discover -s tests -v
sh examples/config_ok.sh
sh examples/config_errors.sh
sh examples/vfs_cases.sh
sh examples/all_ok.sh
sh examples/all_errors.sh
```

Windows: тесты запускаются через `python -m unittest discover -s tests -v`.
Скрипты .sh предназначены для Linux/macOS/WSL/Git Bash; в обычном Windows
те же примеры можно запускать отдельными командами `python -m src.main`.

В `examples/errors/` каждый ошибочный пример выделен в отдельный сценарий:
после первой ошибки стоит `touch MUST_NOT_EXIST`, которая не должна исполниться.
Это необходимо, поскольку один сценарий по заданию прекращается при первой ошибке.
`config_errors.sh` и `all_errors.sh` возвращают успех, если ожидаемые ошибки возникли.

Три источника: minimal (только скрытый .keep для хранения в Git), several
(два файла), demo (вложенные каталоги, включая docs/deep/level3, пробелы, кириллица).
Настоящий пустой каталог отдельно покрывается временными тестовыми данными.

## История и публикация

В поставку включена папка `.git` с пятью последовательными коммитами
Conventional/Scoped Commits. В каждом из первых четырёх коммитов сохранён
соответствующий промежуточный этап; последний содержит итоговую реализацию.
Автор коммитов — техническое имя `Project Author`, а не данные студента.

```sh
git log --oneline --reverse
```

Для сдачи требуется публичный репозиторий. Он не создан автоматически.
Создайте пустой репозиторий в выбранном Git-сервисе (без README и .gitignore),
затем из распакованной папки выполните, заменив адрес своим:

```sh
git remote add origin YOUR_REPOSITORY_URL
git push -u origin main
```

Не загружайте ZIP как файл репозитория и не выполняйте повторный `git init`:
публиковать нужно содержимое с уже подготовленной историей. Сам ZIP — только
упаковка передачи проекта; он не входит в отслеживаемые Git файлы.
Укажите ФИО и группу в README перед сдачей отдельным коммитом документации.
Для новых коммитов настройте собственные `git config user.name` и `user.email`.

Проверка промежуточного этапа без изменения основной папки:
`git worktree add ../stage1 HASH`, где HASH — хеш нужного коммита.
Запустите `python3 -m src.main` из ../stage1 и покажите заглушки ls/cd.
Удаление временной рабочей копии: `git worktree remove ../stage1`.
