# Практическая работа №1. Вариант 28

Этап 1: CLI, реальные username и hostname, кавычки, заглушки ls/cd,
exit и обработка ошибок. Python 3.10+, внешние зависимости не нужны.

Запуск: `python3 -m src.main`. Тесты: `python3 -m unittest discover -s tests -v`.

Пример: `ls "a b"`, `cd /`, `unknown`, `ls "`, `exit`.

Этап 2: --vfs, --script, --batch; сценарий прекращается при ошибке.

Этап 3: снимок каталога VFS в памяти, примеры трёх размеров.

Этап 4: ls [-al], cd, du [-sa] (байты), tail [-n N].

## Запуск и проверка

Команды ниже рассчитаны на Windows PowerShell в терминале PyCharm.
Откройте корень проекта — папку, в которой находятся `README.md`,
`run.bat` и `src`. Терминал открывается сочетанием Alt+F12.
Нужен Python 3.10 или новее; внешние пакеты не требуются.

### PowerShell и эмулятор

Смотрите на последнюю строку терминала, где находится курсор:

| Приглашение | Где выполняется ввод | Доступные команды |
| --- | --- | --- |
| `PS C:\Users\...>` | PowerShell Windows | `git`, `python`, `$LASTEXITCODE` |
| `Asus@DESKTOP-…:/$` | Запущенный эмулятор | `ls`, `cd`, `du`, `tail`, `touch`, `chown`, `exit` в зависимости от этапа |

Имя пользователя, имя компьютера и виртуальный путь могут отличаться.
`python -m src.main` запускает эмулятор из PowerShell.
`exit` внутри эмулятора завершает программу и возвращает в PowerShell.
`exit` в самом PowerShell закрывает терминал.
Старый вывод остаётся на экране как история; это не повторный запуск программы.

### Переключение веток

Если эмулятор запущен, сначала введите в нём `exit`.
Дождитесь приглашения `PS C:\...>`, затем выполните:

```powershell
git branch
git switch stage4-commands
python -m src.main
```

`git branch` отмечает текущую локальную ветку звёздочкой.
Если ветка ещё не создана локально, `git branch -a` покажет также ветки `origin`;
обычный `git switch ИМЯ_ВЕТКИ` создаст локальную ветку по одноимённой ветке `origin`.
Вводите команды по очереди. Если переключение завершилось ошибкой,
остановитесь до запуска программы и проверьте сообщение Git.

| Версия | Имя ветки | Возможности |
| --- | --- | --- |
| Этап 1 | `stage1-repl` | Ввод, кавычки, заглушки `ls`/`cd`, ошибки, выход |
| Этап 2 | `stage2-config` | Параметры запуска и стартовые сценарии |
| Этап 3 | `stage3-vfs` | Загрузка каталога VFS в память и проверка источника |
| Этап 4 | `stage4-commands` | Работающие `ls`, `cd`, `du`, `tail` |
| Этап 5 | `stage5-extra` | Дополнительные `touch`, `chown` |
| Итоговая версия | `main` | Все этапы и последующие исправления |

Git показывает файлы выбранного этапа: на ранних ветках файлов меньше.
При возврате на `main` файлы итоговой версии снова появятся.
Переключение ветки само по себе не запускает программу.
При ошибках о локальных изменениях используйте `git status` и `git diff`;
не удаляйте изменения принудительно.
Если после переноса проекта на Windows Git ошибочно видит изменения прав
`.sh`-файлов, для этого репозитория можно установить
`git config core.fileMode false`. Содержимое файлов эта настройка не меняет.

### Этап 1: ввод и разбор команд

В PowerShell:

```powershell
git switch stage1-repl
python -m src.main
```

Внутри эмулятора, по одной строке:

```text
ls "hello world"
cd "space dir"
unknown
exit
```

Ожидается `ls: ['hello world']` и `cd: ['space dir']`.
Это заглушки: каталог пока не меняется. После `unknown` появляется ошибка,
но ввод продолжается; после `exit` снова появляется PowerShell.

### Этап 2: параметры и сценарии

В PowerShell:

```powershell
git switch stage2-config
python -m src.main --script examples/stage2.txt --batch
$LASTEXITCODE
```

Выводятся параметры, команды сценария и результаты заглушек.
Ожидаемый код завершения — `0`.
Проверка остановки на первой ошибке:

```powershell
python -m src.main --script examples/error.txt --batch
$LASTEXITCODE
```

Ожидается ошибка неизвестной команды на строке 1 и код `1`.
Следующая команда `ls` из сценария не выполняется.

### Этап 3: источник виртуальной файловой системы

В PowerShell:

```powershell
git switch stage3-vfs
python -m src.main --vfs examples/vfs/demo --batch
$LASTEXITCODE
python -m src.main --vfs missing-folder --batch
$LASTEXITCODE
```

Первый запуск загружает каталог и завершается с кодом `0`.
Второй ожидаемо сообщает об отсутствующем источнике и возвращает `1`:
каталога `missing-folder` в проекте нет. На этом этапе `ls` и `cd`
ещё остаются заглушками. Данные источника читаются в память.

### Этап 4: автоматическая проверка команд

В PowerShell:

```powershell
git switch stage4-commands
python -m src.main --script examples/stage4.txt --batch
$LASTEXITCODE
```

`stage4.txt` — один сценарий из 22 команд. Он автоматически проверяет
`ls` и его флаги, переходы `cd`, пути с пробелами, `tail` с разным числом строк,
несколько файлов, `du` и его флаги, затем выполняет `exit`.
Ожидаемый код завершения — `0`.
Каждая команда печатается перед результатом; другие файлы сценариев
этот запуск не выполняет. Код `0` означает успешное выполнение команд;
проверки ожидаемых значений находятся в тестах итоговой версии.

Для ручной проверки запустите `python -m src.main` и введите внутри:

```text
ls
cd docs
tail -n 2 notes.txt
du -s /
exit
```

`tail` должен вывести строки 14 и 15. `du -s /` показывает суммарный размер
файлов в байтах; значение может различаться при LF/CRLF в исходных файлах.

### Этап 5: изменения в памяти

В PowerShell:

```powershell
git switch stage5-extra
python -m src.main --script examples/stage5.txt --batch
$LASTEXITCODE
```

Ожидаемый код — `0`. Сценарий создаёт виртуальные файлы через `touch`,
изменяет владельца и группу через `chown` и показывает результат через `ls`.
Для ручной проверки запустите `python -m src.main` и введите внутри:

```text
touch test.txt
ls -l test.txt
chown student:students test.txt
ls -l test.txt
exit
```

У файла появится владелец `student` и группа `students`.
Изменения существуют только в памяти. После перезапуска виртуальный
`test.txt` исчезнет; настоящие файлы на диске не изменяются.

### Все текстовые сценарии итоговой версии

Эту проверку выполняйте на `main` в PowerShell:

```powershell
git switch main
```

Вставьте следующий блок целиком. При несоответствии ожидаемому коду
проверка остановится с исключением; сообщение об успехе не появится.

```powershell
& {
    foreach ($script in @("examples/stage2.txt", "examples/stage4.txt", "examples/stage5.txt")) {
        python -m src.main --script $script --batch
        if ($LASTEXITCODE -ne 0) { throw "Не прошёл сценарий: $script" }
    }
    $errors = @("examples/error.txt") + @(Get-ChildItem examples/errors/*.txt | Select-Object -ExpandProperty FullName)
    foreach ($script in $errors) {
        python -m src.main --script $script --batch
        if ($LASTEXITCODE -ne 1) { throw "Неверный результат проверки: $script" }
    }
    Write-Host "ВСЕ СЦЕНАРИИ ПРОШЛИ ПРОВЕРКУ" -ForegroundColor Green
}
```

Во второй части сообщения об ошибках ожидаемы: сценарии содержат
намеренно неправильные команды. Проверяется, что программа возвращает `1`.
Это запуск текстовых сценариев эмулятора; `.sh`-скрипты этим блоком не запускаются.

### Автоматические тесты

В PowerShell, после выхода из эмулятора:

```powershell
git switch main
python -m unittest discover -s tests -v
```

В итоговой версии ожидается `Ran 24 tests` и `OK`.
На Windows тест создания символической ссылки может быть пропущен,
если ОС не разрешает создать ссылку: в этом случае допустимо `OK (skipped=1)`.
У промежуточных веток набор тестов меньше; на этапе 4 — три теста парсера.

### Скрипты операционной системы

В Linux, macOS или WSL, где установлены `sh` и `python3`, на ветке `main`
можно дополнительно выполнить из корня проекта:

```sh
sh examples/config_ok.sh
sh examples/config_errors.sh
sh examples/vfs_cases.sh
sh examples/all_ok.sh
sh examples/all_errors.sh
```

Это отдельные проверки параметров запуска, источников VFS,
успешных сценариев и обработки ошибок. Каждый `.sh` должен завершиться
с кодом `0`, включая проверки ожидаемых ошибок.
Обычный PowerShell не исполняет `.sh` напрямую.
Для повседневной работы после проверки оставьте выбранной ветку `main`.
