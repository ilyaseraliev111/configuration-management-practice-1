# Что показать на защите

1. Открыть историю `git log --oneline --reverse`: пять этапов.
2. Для этапа 1 открыть первый коммит через git worktree (инструкция в README).
   Ввести `ls "a b"`, `cd 'two words'`, `ls ""`: заглушки сохраняют аргументы.
   Ввести неизвестную команду, незакрытую кавычку и `exit extra`.
   Показать продолжение работы после ошибок и завершение через `exit`.
3. В итоговой версии показать настоящие username/hostname в приглашении.
4. Запустить stage4.txt: вложенные пути, кавычки, ls, cd, du, tail.
5. Запустить stage5.txt: создание файла, обновление времени, смена владельца,
   рекурсивное изменение группы и подтверждение через `ls -l`.
6. Запустить errors/01.txt: ошибка на первой строке, вторая не выполняется.
7. Перезапустить приложение: виртуальные изменения исчезают.
8. Запустить тесты: проверяется в том числе неизменность реальных файлов.

## Ответы на вероятные вопросы

**Почему shlex, а не split?** split разбивает аргумент с пробелами внутри
кавычек. shlex учитывает одинарные/двойные кавычки и экранирование.

**Что такое REPL?** Read–Eval–Print Loop: прочитать ввод, разобрать и выполнить,
показать результат, повторить. В Shell это метод repl, разбор — execute.

**Где хранятся файлы?** В словаре VFS.nodes. Ключ — абсолютный виртуальный путь;
значение — Node. Содержимое файла — bytes, поэтому двоичные данные не теряются.

**Почему cd не вызывает os.chdir?** cwd является состоянием эмулятора.
Реальный рабочий каталог процесса не должен меняться.

**Как работает du?** Сначала назначаются размеры файлов; затем размеры
потомков прибавляются родителям снизу вверх. Размер каталога — сумма файлов.

**Как работает tail?** Файл декодируется как UTF-8, разбивается на строки
с сохранением разделителей, берутся последние N строк. N=0 обработан отдельно,
поскольку срез [-0:] иначе вернул бы весь список.

**Что делает chown без root?** Меняет строки owner/group в Node.
Системный вызов chown не используется, настоящие права не нужны.

**Как доказать, что VFS не меняется на диске?** test_source_unchanged сравнивает
байты, UID/GID и mtime реального дерева до и после команд. atime не сравнивается:
чтение само по себе может обновлять время доступа на уровне файловой системы.

**Связь с лекцией 1.** Текстовый диалог, UNIX-пути и отдельные команды для
небольших задач. Конвейеры и перенаправления из общего курса в вариант не входят.

## Соответствие заданию

| Этап | Реализация | Демонстрация |
| --- | --- | --- |
| 1 | CLI, реальные данные ОС, кавычки, заглушки, exit | Первый коммит, tests/test_shell.py |
| 2 | --vfs/--script, отладочный вывод, остановка при ошибке | config_ok.sh, config_errors.sh |

README, .gitignore, src, tests и скрипты запуска присутствуют.
История отражает последовательную разработку. Публичная публикация и очная
демонстрация остаются действиями студента; их нельзя заменить локальной проверкой.
